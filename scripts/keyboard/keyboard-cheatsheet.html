These are the only positions present on all six keyboards. The bottom-left corner is deliberately not an anchor — it is Ctrl on the XPS and Pixelbook but fn on both MacBooks. That is the whole reason Caps carries Control. On Linux, Cmd is Super; on macOS it is Command.

⌥ [ and ⌥ ] are unusable. They transmit ESC [ and ESC ] — the CSI and OSC introducers — which no program can distinguish from the start of a real escape sequence. Hence ⌥ , and ⌥ . for previous and next window.

Focus & resize Alt — one key crosses tmux panes and vim splits

In a pane running vim the key is forwarded to vim; anywhere else it moves the tmux pane. Letters and arrows are interchangeable everywhere, not only in vim's normal mode.

Word motion stops at the start of the next word in all four layers — not the end of the current one. zsh, vim's w and tmux's next-word already agreed; readline's forward-word was the sole dissenter, so bash binds vi-fword instead. PgUp in a plain shell pane enters tmux scrollback; in anything that pages its own content — vim, less, man, top — the key passes straight through.

Where each binding lives

A key is bound in the outermost layer that can still see it. Bind it too far out and the layers inside never receive it; too far in and an outer layer eats it first.

Binding groupFileWhy there
Caps → Control, Alt/Super swap scripts/keyboard/{linux,macos}/apply.sh The OS layer is the only one that can rewrite a keysym. Everything above sees the result.
Per-machine deviations scripts/keyboard/linux/machines/ The Pixelbook has no physical Super key, so it needs a different xkb rewrite.
Command shortcuts scripts/keyboard/linux/terminal.sh Super has no byte encoding, so the emulator is the innermost layer that can see it. iTerm2 does this natively on macOS.
Alt — panes, windows, paging .tmux.conf Root table, not behind the prefix, because frequent operations must never be chained.
Alt — vim splits .vimrc tmux forwards these only when the pane runs vim. Without the vim half the keys still move panes — a floor, not a break.
Line editing, shells .shell/.common.d/keys.sh readline and ZLE cannot read tmux's or vim's tables. The duplication is real and accepted.
Line editing, scrollback .tmux.conf Both copy-mode and copy-mode-vi, since mode-keys follows $EDITOR.
Prompt width .shell/.bashrc Not a binding, but the cursor keys draw in the wrong column without it.

Conflicts this arrangement avoids

Each is a case where two layers wanted the same key, and the fix was deciding which layer owns it.

CollisionResolution
gnome-terminal tabs vs tmux windows gnome-terminal ships switch-to-tab-N on <Alt>N. Moved to <Super>N — the emulator is outermost, so keeping Alt would mean tmux never sees it.
GNOME Shell dash vs terminal tabs Moving tabs to Super then collides with switch-to-application-N, further out still. Released first — outermost layer cleared before the next one in.
tmux pane focus vs vim split focus tmux owns the key and forwards it when the pane runs vim. vim-tmux-navigator behaviour without the plugin.
tmux scrollback vs a program's own pager tmux owns PgUp, forwarding whenever the pane pages its own content — tested as alternate_on or a command-name match, because LESS="-EXFR" keeps less off the alternate screen.
⌃ ← / ⌃ → in tmux Deliberately not bound in tmux's root table, so they pass through untouched. Word motion belongs to whatever is reading the line.
The rxvt form of ⌃ → ESC [ 5 C is safe for readline and ZLE, but vim decodes the tail as 5C — change five lines — which destroys the buffer. Bound in the shells and nowhere else.
⌥ ← as readline word motion Left alone rather than unbound: tmux takes the key first, so it is unreachable inside tmux and harmless outside it, where there are no panes.

Two settings no script can set

iTerm2 — Option must reach the tty Profiles → Keys → General → Left Option key and Right Option key → Esc+. Without this, Option never reaches tmux or vim and half this sheet is dead.
Touch Bar MacBook Pro Settings → Keyboard → Touch Bar shows F1–F12, with fn for the Control Strip. Otherwise the machine has no Escape and no function row.
Applied by scripts/keyboard/linux/apply.sh and scripts/keyboard/macos/apply.sh — both idempotent, self-guarding, and no-ops on the wrong platform.
